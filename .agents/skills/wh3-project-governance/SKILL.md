# WH3Fallout工程基线治理

执行本项目的[工程实施与治理总纲](../../../项目工程实施框架.md)，不另立治理制度或新增每轮审计文档。先确认项目根目录，读取该目录`AGENTS.md`；不要把相邻项目的分支模型、治理技能或文档索引规范搬入本项目。

## 读取与定界

1. 先读总纲第九节治理流程、第二／五／十节权威位置与记录规则、第十一节五对话协作，再读`工程/当前状态.json`、工程日志最近相关记录和`文档导航.md`。
2. 按用户要求区分只读检查／建议与实施治理，明确涉及的领域、正文和代码范围。默认局部治理，不因一个过期段落全库重排。
3. 需要知道并行写入和最新用户方向时，只读核对对应原聊天近期状态；身份与通信方法见[跨对话协作](../../../工程/跨对话协作.md)。治理不自动授权发送测试消息、唤醒其他领域或启动游戏。没有跨聊天工具时，可凭明确适用的落盘证据继续，说明实时状态未核实。

## 按证据归拢

- 用`rg`定位相关对象和引用，阅读正文、真实实现、构建清单和报告。Git仅辅助查看已指定文件，不据工作区改动归因任务，不触碰无关并行修改。
- 每项问题判断：唯一权威位置是什么，已确认／候选／历史／未知分别有哪些依据；保留、更正、合并、迁移、归档或删除解决什么实际成本。
- 对照事实而不是复制最新措辞。已解决接口从当前阻塞移除；旧版本通过不覆盖新输入，恢复到before不等于全局清理。
- 种族及派系目录保持用户确认结构，不按数量压缩。其他领域按稳定内容职责组织；只为真实独立内容拆文档，不按对话、轮次或模板填满率制造文件。
- 当前正文就地更新，只留一处当前进展；过程写现有日志，执行细节归对应证据，共享状态只保存接续必需的任务与引用。不要把每份回传再复制成独立报告。

## 实施与协作

有实施授权时做最小一致改动，同步必要入口、引用和替代关系。A维护全局制度、状态和日志；领域维护自己正文。遇到正在编辑的文件，只协调冲突范围，无关任务继续；部分依赖先明确接口，不建立整轮等待屏障。

跨领域冲突、用户原则变化、技术限制改变玩法或明显成本增长交A与用户处理，不能用治理悄悄替换产品决策。删除、不可逆覆盖、批量迁移、关键证据清理及外部变更按具体授权处理；用户已明确的操作不重复索要同一许可。保留原版、存档、未知来源文件、不可再生产编辑源和仍被引用证据。

治理授权不恢复暂停的技术验证，不默认构建、测试、部署或Git提交推送。若需执行制作工具，先检查是否写共享状态／日志及占用外部资源，约定独占与恢复责任；不在治理中顺便运行。

## 收口

按总纲9.5作与改动匹配的静态自检：当前权威与负责者、引用路径、实际停点、源与产物关联、证据适用范围、并行安排、未越界修改。技能或JSON只核元信息与结构，不把静态检查写成游戏／平衡通过。

A更新已有共享状态和连续日志，领域更新已有总览；保留未知与未执行项。最终回复说明实际范围、主要更正、残余问题及下一步；只读检查则报告建议，不写成已实施。不要新建治理报告、并行台账、启动提示词或未被消费的辅助脚本。
