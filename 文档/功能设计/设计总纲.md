# 设计总纲

更新日期：2026-11-02。本文是功能设计的总领入口，种族内容按目录分别维护；设计状态不等于技术验证状态。

## 设计原则与推进方式

项目愿景、用户已确认方向及边界以[项目概念设计](../../项目概念设计.md)为准；原版比较以[战锤设计对比参考表](../原版参考/战锤设计对比参考表.md)为依据。

辐射提供背景与设定，战锤3第9版全DLC提供机制和玩法。先根据特色选择具体原版对象，再组合与换皮；不从头发明系统再寻找实现方式。不把原型存在等同于跨文化移植通过。

先完成种族概述与原型，再整理共享兵种、人物、建筑、科技和能力，最后填写种族内各派系的开局与差异。种族在此对应既有“文化”分组，不擅自改变引擎结构或候选资格。先迁移已有内容，未知项继续待定。

每轮直接更新责任正文，不按对话追加提案。原型明确、玩法衔接、差异合理、成本可控且未决项清楚，是初设完成口径；不以文件数量、名单长度或填满率衡量完成。

多对话职责以[工程框架第十一节](../../项目工程实施框架.md#十一多对话实施与整合2026-11-02确认)为准。种族与派系对话完整推进兵表、建筑招募、人物、科技和内部派系，不再按这些专业拆分。世界与战役负责位置与连接；战斗装备与人物构筑负责共通规则及邮差专项；技术职责负责真实实现与证据。跨领域内容引用唯一正文，依赖与冲突明确回传。

本总纲的模板、功能总览和种族进展由种族与派系职责维护；全局阶段、共享资源与工程决定由整体工程对话维护。五个对话已启动，现有成果从“当前设计进展与复阅入口”和共享工程状态继续，不重新初始化，也不再维护启动提示词。

### 需要用户复阅的方向点

1. **豪斯的战役／战场身份**：原身留在幸运38，由专属代理统帅出征；或豪斯以遥控代理机体作为传奇领主。建议后一种作为优先方向，更接近战锤常规领主流程，但它是尚未获得用户确认的架空表现，不能直接据此选最终模型与装备。
2. **主教的个人表现**：大型地面生物领主与固定终端／设施指挥身份的区别影响人物资产和出征体验。现阶段只定组织化军队方向，暂不擅自把主教做成普通食人魔外形。可先比较与其身份接近的现成大型／平台原型，再提交具体表现选择。

以上不改变现有派系定位。NCR“支持少者为叛军”、封闭地区特殊入口、三类独立避难所与邮差有限构筑均保留。遇到技术无法满足已确认目标时报告差异，不能以本轮原型选型默默替换。

### 制作交接前的实际依赖

共享兵表中已有本地定位证据的对象与只是候选的对象必须分别处理。下一阶段先核具体原版单位、建筑、科技和能力记录，确认动作、目标筛选、费用、权限和生命周期；设计者不编造表键，也不以额外自制面板填补未知项。这些问题交由技术职责在其计划内处理，不在本对话新增验证执行或中断当前试验。

## 内容模板与维护口径

### 1. 种族概述

- 概述、背景依据与必要架空调整。
- 一句话玩法定位、核心特色、主要强弱点。
- 战锤整体参考原型与补充组件，采用理由。
- 地图分布概念，具体位置引用地图或派系文档。
- 种族内派系清单、可玩／AI定位及差异摘要。
- 共享兵表、人物、建筑、科技、能力的结构摘要及链接。
- 基本经营、招募、补员、作战与成长如何衔接。
- 首批内容范围、未决方向与技术依赖摘要。

这是该种族的阅读入口，不再复制其他文档的完整条目。

### 2. 种族机制

- 机制名称、题材对应、适用派系及例外。
- 战锤具体原型、采用部分、舍弃部分及理由。
- 玩家如何使用；成本、收益、目标、解锁、限制与反制沿用何种规则。
- 与建筑、人物、兵种、科技的连接。
- 多个现成组件之间是否重复收费、重复加成或权限冲突。
- 原型出处、设计状态、技术证据与必要备选。

共享机制在此维护。仅某派系使用的短小机制放在该派系文件；复杂专属机制也应明确唯一责任位置，其他文档引用。

### 3. 兵种设计

先给兵表总览，再在同一文档中按单位填写兵种／兵牌条目：

- 名称、已有标识、背景、种族与派系权限。
- 分类、战术职责、优势弱点与反制。
- 具体战锤单位原型、沿用行为与必要修改。
- 编制、关键属性、武器、近战／射击方式；初期可写沿用原型。
- 主动／被动能力、部署、心理与抗性等适用标签。
- 招募来源、层级、费用、时间、维护、容量与补员例外。
- 科技与人物加成引用，变体关系。
- 模型、骨架、动作参考与兵牌识别要点；不要求本阶段完成美术制作规格。
- 设计状态、技术证据与缺口。

兵牌是单位视觉表达，兵种是玩法对象；两者同条记录，但不能混为一项完成状态。

### 4. 领主与事务官设计

- 普通／传奇、领主／事务官的类型总览。
- 每个人物的身份、定位、归属、获取与唯一性。
- 战锤原型、个人特性、技能树结构、装备与坐骑方向。
- 自身、所率军队、地区与派系效果分别标明。
- 独立行动、嵌入效果与战场能力。
- 受伤、死亡、返回、解散重招等沿用规则与必要例外。
- 专属内容、资产及技术依赖。

派系文件介绍领袖及派系意义，完整人物条目在此维护。跨种族人物未来由独立责任入口统一维护，邮差完整规则由跨种族专项维护。

### 5. 建筑设计

先列建筑链总览，再逐链填写：

- 名称、主题、用途与原版建筑链原型。
- 种族／派系权限，主城／小城／指定地点等位置限制。
- 各等级名称、前置、成本、时间。
- 收入、发展、秩序等效果及本地／省份／全局范围。
- 招募、容量、驻军和机制解锁引用。
- 槽位取舍与成长作用。
- 占领、损坏、摧毁、重建的沿用规则及例外。
- 资产、技术依赖和证据。

### 6. 科技设计

先列科技树分支与前置关系，再逐节点填写：

- 名称、主题、所属分支与适用派系。
- 原版科技或效果原型。
- 前置、解锁条件、研究时间。
- 效果、对象、范围及叠加规则。
- 与建筑解锁、技能和专属升级的分工。
- 图标主题、设计状态与依赖。

不为每个节点重复填写整套背景，不在未必要时重做所有数值。

### 7. 法术与能力设计

- 名称、辐射表现、原版具体能力原型。
- 来源：人物、兵种、装备、军队或建筑等。
- 类型：法术、绑定能力、主动技能、被动等。
- 目标、筛选、效果、释放形态、射程、范围、延迟与持续。
- 资源、次数、冷却及其他原生限制。
- 友伤、治疗上限、召唤退场、叠加及反制等适用项。
- 动作、特效、声音方向；玩法沿用与表现替换分开。
- 设计状态、技术证据与依赖。

可容纳药物、指挥、炮击、空援、毒气和维修，不强制套八风法系。兵种和人物只引用能力条目，不另写一套不同数值。

### 8. 种族内各派系

每个派系一份文档：

- 背景概述与一句话玩法。
- 所属种族、共享内容引用及例外。
- 地图位置、初始领土、邻居、关系、威胁与机会。
- 派系领袖及传奇人物引用。
- 派系特性：效果、作用对象、范围、原型及代价。
- 专属机制：原型与必要差异；没有独有机制也可成立。
- 专属兵种、人物、建筑、科技、能力的差异清单及引用。
- 起始军队与经营基础。
- 开局行动、中期成长与长期胜利目标。
- 与同种族派系的实际区别。
- 首批范围、设计状态、关键分歧和技术依赖。

专属单位等完整条目仍在种族对应内容文档维护，并标注派系限制；派系文件只负责归属和差异说明，避免两处维护同一单位数据。

## 统一记录与引用规则

每个对象按需要记录以下信息，不重复套长表头：

| 项目 | 规则 |
| --- | --- |
| 背景依据 | 区分辐射设定、用户决定和助手架空建议 |
| 原型 | 写具体战锤对象及采用部分，不能只写“参考帝国／鼠人” |
| 改动 | 标明直接沿用、换皮、数据调整或组合现成组件及理由 |
| 设计状态 | 候选、初设、用户确认、搁置；确认注明范围 |
| 技术证据 | 未核、已定位、局部验证、目标范围已验证；引用证据和实际边界 |
| 未填项 | 写待定及原因；无此项写不适用；共享项直接引用 |
| 数值 | 优先沿用原型，需要偏离才说明理由；不伪填精确数值 |
| 唯一责任 | 同一规则或条目只在一处维护，其他地方链接引用 |

概念成立、原型存在、数据已定位、实际游戏验证通过是不同结论。

## 设计推进顺序

1. 沿用总纲、种族目录和各文档职责；有实际内容需要时调整结构并同步入口，不为每轮工作重建模板。
2. 每次选一个种族，先完成种族概述与机制原型选择，不直接从某个派系写起。
3. 补该种族共享兵表、建筑、科技、人物和能力，使基本玩法能够衔接；按依赖往返，不机械要求一份写完才能读下一份。
4. 再填写种族内各派系的定位、开局、特性与专属差异。
5. 做种族内及跨种族比较，检查重复、全能化和不必要制作成本。
6. 直接更新正式责任正文并同步导航与引用，标清候选、初设与已确认范围；仅影响方向的关键分歧向用户提问。技术验证由承担该职责的对话按授权独立推进。

每轮更新对应正文，不把连续讨论追加成越来越长的历史稿。完成标准是原型明确、循环衔接、职责清楚、差异合理及未知项可追踪，不是填满所有栏目。

### 五、派系增多的实际设计方法

1. 优先增加同文化不同开局和普通 AI，而非每次增加一套兵表、建筑、科技和资源。
2. 通用 AI 至少有定位：守备、扩张、劫掠、缓冲或贸易。不同模板改军队倾向、初始关系与起点，不必各有专属面板。
3. 允许强弱不对称：小帮派可以弱，但应能形成地理和外交意义，而不是无限刷新经验。
4. 地图先布主战线、支线冲突和地方势力，再决定聚落密度；不靠无意义拉长行军距离扩大面积。
5. 不让每个新名字都获得完整独立资源；原子神教等存在感可由高辨识度的组织内容承担。

### 六、原型与技术待定

学院合成人和新增民兵是否共享现有文化，主教的战斗形态，铁路组织的表现，原子神教事件位置，新增 AI 数量与地图性能，均未核验。

本表先完成内容占位，不宣布全部可玩，也不进入批量资产制作。实际活跃派系数量需与回合等待、AI 行动和地图密度一起评估。

背景核对：[The Master](https://fallout.fandom.com/wiki/Master)、[Unity](https://fallout.fandom.com/wiki/Unity)。其他新增组别目前为身份候选，详细原作内容在具体选型时再核对；不要求其年代共存。

重点比较 NCR 与大可汗的射击体验、军团与部落的突击体验、维加斯与大山的机器人体验、兄弟会与英克雷的精锐体验。差异优先由兵表职责、开局和现成效果承担，不为了区别而添加资源系统。

助手直接在各责任文档中完成原型选型和内容细化；种族、派系及地图分别维护，不以追加提案代替更新正文。首版数量不由候选表自动决定。

邮差与避难所分别只在[邮差设计](邮差传奇事务官设计.md)、[避难所设计](避难所玩法初设.md)维护详细规则。避难所三类完全独立；封闭型开启后果纯随机，不预警、不保底、不按时期调整收益，也不转成其他两类。

### 7.1 单位设计口径

以下是具备战术职责的第一批单位槽位，不是按原作武器穷举。代表单位与完整兵表均在各种族的兵种设计文档维护，本节只维护共通口径。所有名称和原型均为助手设计选择，仍待目标版本数据定位与资产适配；不声称已制作。

阶段“初／中／高”表示玩法获得阶段，不直接等于建筑1／3／5级。每行编制、速度、质量、攻击与射击行为默认继承拟用原型，再调整必要数值；未核对前不虚填模型数。来源骨架相同但武器行为不同的单位仍要逐项适配。

同文化领主默认使用共同兵表，专属单位与招募权限另记。通用伤害不按“实体／能量”一刀切：激光可取魔法攻击表现，但破甲与法术来源仍独立；高斯不因是高科技自动获得魔法属性。普通低级兵要保留守备、补充或专业用途，不全被高级兵替代。

表中“限制／反制”决定需要保留的取舍，不先写最终费用与百分比；容量只用于确有理由的精锐组，不把全部文化改为容量经营。

### 7.12 共享模板、权限与未填类别

本节初设共105个单位槽位，包含文化间可复用的基础人形、战兽、炮兵和机械平台；不代表相同数量的独立骨架或首版全部制作承诺。精确总数随合并同质变体调整，地图规模和兵表数量不互相强制绑定。

| 对象 | 基础模板与权限方案 | 暂不增加的内容 |
| --- | --- | --- |
| 普通掠夺者 | 普通近战、手枪、步枪、少量专业武器和战兽；每个AI取部分组合 | 不各建独立科技和全套精锐 |
| 民兵／义勇兵 | 共享地方守备、普通枪手、适量炮兵；用人物、驻军与起点体现组织 | 暂不新建完整义勇兵文化机制 |
| 枪手 | 普通人类专业兵，少量重武器与高级护卫 | 不自动获得英克雷资料与空中投送 |
| 学院 | 人形合成人先用普通／精锐射手与近战骨架，技术支援采用既有能力 | 是否独立文化须看实际差异；不因合成人必然新增机械修复系统 |
| 智慧死亡爪集团 | 以死亡爪单体／大型近战、战兽和少量控制者支援组合，暂为AI | 单体过多的经济与自动结算未确定，不默认可玩完整度已达标 |
| 马德雷守军 | 幽灵人近战、特殊恢复或消散、小量适合本区的射手与支援 | 不直接套用全部尸鬼政治与火箭分支 |
| 各部落 | 共享轻装步兵、矛手和普通射手，按领主增加少量精锐 | 不为了来自不同地区就拆多套科技树 |

战车重点先放大可汗；常驻科技飞行器优先英克雷，其他派系可用能力空援；军团、大可汗与部落暂不设完整重炮线。反大型职责可由矛兵、专业射击或单体共同承担，不要求每文化同时具备怪兽骑兵、坦克、火箭与全部空军。

所有单位按招募条件、红线单位组、科技对象、驻军与AI招募池建立对应关系；原型只是行为起点，不能把原型原所属种族的隐藏机制全部继承进来。

### 8.1 普通领主与事务官类型

类型先围绕兵表与原型设置；不同文化可共享底层行为，名称与技能组分开。人物类型不是另一个文化，不给每个普通领主独立经济。普通事务官以少量可区分的类型为主，避免把狙击、观察、潜行拆成三套近似英雄。

事务官行动类型只按原型实际支持内容配置。上表名称不保证能刺杀、偷科技或破墙；后续技术定位后填写动作包。人物容量与招募建筑沿文化经营配置，不用传奇英雄填补普通类型缺失。

### 8.2 技能树分工

| 人物 | 通用分支 | 专属／取舍 | 作用边界 |
| --- | --- | --- | --- |
| 普通领主 | 战役行动、军队单位组、个人近战／射击、适用能力 | 两种类型改变红线重点与个人定位 | 红线默认所率军队；派系全局效果另记 |
| 传奇领主 | 对应普通类型主体 | 一组身份分支与一项招牌能力，必要时少量专属装备 | 不把派系特色资源再复制成个人万能技能 |
| 战斗事务官 | 个人战斗、行动、适用部署或能力 | 射击／生存或近战／支援取舍 | 不复制领主全军红线 |
| 医疗／技术事务官 | 恢复、工程／支援能力、嵌入与地区效果 | 恢复与火力支援分支取舍，防无限叠加 | 同一军队多名同类英雄的效果按原型叠加规则审阅 |

各族具体单位组、传奇人物倾向和技能分配只在对应种族的《领主与事务官设计》维护，入口见[种族总览](#种族与派系入口)。不在总纲重复一套红线对象。

### 8.3 建筑链与招募节奏

各族建筑链、层级、招募、容量及驻军在各自《建筑设计》维护，入口见[种族总览](#种族与派系入口)。沿用原版主聚落、收入、发展、治理、军事和防御结构，保留槽位取舍；不因目录统一要求所有种族具备全部类型。

基本成长采用“基础军→专业职责→少数精锐与高级支援”。建筑解锁、科技强化和人物所率军队效果分开；英克雷与好好先生等专属成长例外见本族机制，不重复收取同一许可。

### 8.4 科技树首批节点主题

每个箭头表示一条三节点分支的初设前置，共四条分支、十二个主题节点；只是第一层可审阅研究结构，不宣称是最终完整科技数量。各节点作用范围固定到指定单位组或经营类别，研究时间与数值待游戏数据与成长节奏确定。普通节点不新增研究资源。

经济科技与军事科技并列，让开局有顺序选择。研发加速不允许大山地标、科学家与完整避难所叠加成无限即时研究，具体上限按原版效果与目标版本审阅，不先开发自制研究规则。

## 特色机制与目标入口

各族机制和派系目标由种族正文唯一维护，见[种族总览](#种族与派系入口)。以下只保留尚无独立种族正文承接的商路与非征服组织方向；候选不代表可移植或已实现。

### 9.8 商路与非征服组织

商路先交给商贸城邦／商队公司作为机制候选，而非把豪斯、好好先生强制改成商队派系。玩家是否可直接操控该集团，留待其基础兵表与经营完整度确定；AI商队能力不能仅凭玩家原型存在来推定。暂不为只出现于事件的商人开发完整可操作商队。

天启追随者以医疗／研究事务官、地方设施与任务体现；原子神教以辐射地点、地标和事件体现；铁路组织以潜行人物与有关合成人的任务体现。不为三者强造全国兵表。中国背景内容仅按[素材储备文档](./素材储备/中国背景素材.md)保留准备材料，本节不恢复其派系资格。

### 9.9 本节选型依据

混沌矮人官方介绍支持把锻炉强化、政治席位、商队分开观察，但不证明跨文化移植。[SEGA介绍](https://sega.prezly.com/total-war-warhammer-iii-the-forge-of-the-chaos-dwarfs-is-out-now)

其余具体宿主以本地目标版本数据为最终定位依据；“古墓王式”“高精灵式”“鼠人式”等目前是设计原型，不是已交付模块。

### 10.5 胜利条件工作稿

胜利继续沿用原版任务与战役目标形式，可完成后继续游玩。下表为主题目标组合，不锁定具体城镇数或战斗数；不同领主在共同文化目标上改指定地区和敌人，避免全员统一“占领胡佛水坝”。

后期危机暂不独立制作一套新系统；保留原版结构与已选势力的后续内容入口。凯撒和主教不因强大就同时自动变成所有派系的末日敌人。

## 十三、当前功能方案的自主审阅

| 风险／冲突 | 当前处理 | 后续不能越过的边界 |
| --- | --- | --- |
| 同一城市多个领袖 | 将都市拆为独立聚落、分配不同起点 | 正式地图仍需能承载这些区域，不假装一个城市能同时归属多派系 |
| 地图越大只增加空白 | 环路、支线与地方AI形成可争夺据点 | 精确距离需实际地图与行军数据，不凭草图宣称节奏已合适 |
| 特色机制不断膨胀 | 普通组织共享模板；资源仅英克雷／好好先生等已有方向采用 | 不把名为“政治”“智能”的系统当成无需实现成本 |
| NCR支持被费用余额替代 | 独立记录指挥部背书，支出不直接导致失去合法性 | 背书是脚本／原型待核点，不承诺高精灵UI原封移植 |
| 尸鬼与变种人混为一谈 | 独立兵表、人物与成长；Nightkin归变种人 | 身份与标签要按具体单位配置，不能整体套亡灵或机械 |
| 封闭区域变成一次性副本 | 正常领土、固定入口、占领后持续经营 | 不能在技术受限时私自改回陆路或领奖任务战 |
| 避难所三类混合 | 地图只安排完整与遗址；封闭型事件不升级或转化 | 纯随机不受阶段和调查改变，毁城结果不默默删掉 |
| 邮差通过重招刷全构筑 | 先选变体、永久名额记录、升级替换旧装备 | 物品撤销与生命周期未验证，不能声称已经防住所有绕过 |
| 单位槽位与资产数量混淆 | 兵表现为105个槽位，以各种族兵种文档逐行记录为准 | 计数不是独立资产数，后续合并变体应同步摘要 |
| 资源与功能脱节 | 先做资产族与代表样本，音频分三条路线 | 不拿游戏安装或资料网页替代素材接入结论 |
