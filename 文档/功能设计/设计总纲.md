# 设计总纲

更新日期：2026-11-04。本文是功能设计的总领入口，种族内容按目录分别维护；设计状态不等于技术验证状态。

## 设计原则与推进方式

项目愿景、用户已确认方向及边界以[项目概念设计](../../项目概念设计.md)为准；原版比较以[战锤设计对比参考表](../原版参考/战锤设计对比参考表.md)为依据。

辐射提供背景与设定，战锤3第9版全DLC提供机制和玩法。先根据特色选择具体原版对象，再组合与换皮；原型存在、数据定位和目标玩法验证分别记录。

先完成种族概述与原型，再整理共享兵种、人物、建筑、科技和能力，最后填写种族内各派系的开局与差异。种族在此对应既有“文化”分组，不擅自改变引擎结构或候选资格。未知项保留待定。

领袖优先采用《辐射》系列已有角色，允许跨年代并存；原创人物须标注身份与采用理由。军团正规派系以军团号显示，人物保留本名并加称号，架空番号与称号明确标注。

直接更新责任正文。初设完成口径为原型明确、玩法衔接、差异合理、成本可控且未决项清楚。

多对话职责以[工程框架第十一节](../../项目工程实施框架.md#十一多对话实施与整合)为准。种族与派系对话完整推进兵表、建筑招募、人物、科技和内部派系，不再按这些专业拆分。世界与战役负责位置与连接；战斗装备与人物构筑负责共通规则及邮差专项；技术职责负责真实实现与证据。跨领域内容引用唯一正文，依赖与冲突明确回传。

本总纲的模板、功能总览和种族进展由种族与派系职责维护；全局阶段、共享资源与工程决定由整体工程对话维护。当前设计从下表及各种族概述接续。

### 需要用户复阅的方向点

1. **豪斯的战役／战场身份**：原身留在幸运38，由专属代理统帅出征；或豪斯以遥控代理机体作为传奇领主。建议后一种作为优先方向，更接近战锤常规领主流程，但它是尚未获得用户确认的架空表现，不能直接据此选最终模型与装备。
2. **主教的个人表现**：大型地面生物领主与固定终端／设施指挥身份的区别影响人物资产和出征体验。现阶段只定组织化军队方向，暂不擅自把主教做成普通食人魔外形。可先比较与其身份接近的现成大型／平台原型，再提交具体表现选择。

以上不改变现有派系定位。NCR“支持少者为叛军”、封闭地区特殊入口、三类独立避难所与邮差有限构筑均保留。遇到技术无法满足已确认目标时报告差异，不能用原型选型改变已确认目标。

待核组合统一见[技术待验证集中入口](../可行性验证/首批可行性验证方案.md#十当前设计组合待验证清单)。

### 制作交接前的实际依赖

共享兵表中已有本地定位证据的对象与只是候选的对象必须分别处理。下一阶段先核具体原版单位、建筑、科技和能力记录，确认动作、目标筛选、费用、权限和生命周期；设计者不编造表键，也不以额外自制面板填补未知项。这些问题交由技术职责在其计划内处理，实际执行按共享工程状态的授权安排。

## 内容模板与维护口径

正文写作遵循[项目工程框架9.2](../../项目工程实施框架.md#92-文档按稳定内容组织)；下列模板规定内容职责与字段。

### 1. 种族概述

- 概述、背景依据与必要架空调整。
- 一句话玩法定位、核心特色、主要强弱点。
- 战锤整体参考原型与补充组件，采用理由。
- 地图分布概念，具体位置引用地图或派系文档。
- 种族内派系清单、可玩／AI定位及差异摘要。
- 共享兵表、人物、建筑、科技、能力的结构摘要及链接。
- 基本经营、招募、补员、作战与成长如何衔接。
- 首批内容范围、未决方向与技术依赖摘要。

这是该种族的阅读入口，不再复制其他文档的完整条目。

### 2. 种族机制

- 机制名称、题材对应、适用派系及例外。
- 战锤具体原型、采用部分、舍弃部分及理由。
- 玩家如何使用；成本、收益、目标、解锁、限制与反制沿用何种规则。
- 与建筑、人物、兵种、科技的连接。
- 多个现成组件之间是否重复收费、重复加成或权限冲突。
- 原型出处、设计状态、技术证据与必要备选。

共享机制在此维护。仅某派系使用的短小机制放在该派系文件；复杂专属机制也应明确唯一责任位置，其他文档引用。

### 3. 兵种设计

先给兵表总览，再在同一文档中按单位填写兵种／兵牌条目：

- 名称、已有标识、背景、种族与派系权限。
- 分类、战术职责、优势弱点与反制。
- 具体战锤单位原型、沿用行为与必要修改。
- 编制、关键属性、武器、近战／射击方式；初期可写沿用原型。
- 主动／被动能力、部署、心理与抗性等适用标签。
- 招募来源、层级、费用、时间、维护、容量与补员例外。
- 科技与人物加成引用，变体关系。
- 模型、骨架、动作参考与兵牌识别要点；不要求本阶段完成美术制作规格。
- 设计状态、技术证据与缺口。

兵牌是单位视觉表达，兵种是玩法对象；两者同条记录，但不能混为一项完成状态。

### 4. 领主与事务官设计

- 普通／传奇、领主／事务官的类型总览。
- 每个人物的身份、定位、归属、获取与唯一性。
- 战锤原型、个人特性、技能树结构、装备与坐骑方向。
- 自身、所率军队、地区与派系效果分别标明。
- 独立行动、嵌入效果与战场能力。
- 受伤、死亡、返回、解散重招等沿用规则与必要例外。
- 专属内容、资产及技术依赖。

派系文件介绍领袖及派系意义，完整人物条目在此维护。跨种族人物未来由独立责任入口统一维护，邮差完整规则由跨种族专项维护。

### 5. 建筑设计

先列建筑链总览，再逐链填写：

- 名称、主题、用途与原版建筑链原型。
- 种族／派系权限，主城／小城／指定地点等位置限制。
- 各等级名称、前置、成本、时间。
- 收入、发展、秩序等效果及本地／省份／全局范围。
- 招募、容量、驻军和机制解锁引用。
- 槽位取舍与成长作用。
- 占领、损坏、摧毁、重建的沿用规则及例外。
- 资产、技术依赖和证据。

### 6. 科技设计

先列科技树分支与前置关系，再逐节点填写：

- 名称、主题、所属分支与适用派系。
- 原版科技或效果原型。
- 前置、解锁条件、研究时间。
- 效果、对象、范围及叠加规则。
- 与建筑解锁、技能和专属升级的分工。
- 图标主题、设计状态与依赖。

不为每个节点重复填写整套背景，不在未必要时重做所有数值。

### 7. 法术与能力设计

- 名称、辐射表现、原版具体能力原型。
- 来源：人物、兵种、装备、军队或建筑等。
- 类型：法术、绑定能力、主动技能、被动等。
- 目标、筛选、效果、释放形态、射程、范围、延迟与持续。
- 资源、次数、冷却及其他原生限制。
- 友伤、治疗上限、召唤退场、叠加及反制等适用项。
- 动作、特效、声音方向；玩法沿用与表现替换分开。
- 设计状态、技术证据与依赖。

可容纳药物、指挥、炮击、空援、毒气和维修，不强制套八风法系。兵种和人物只引用能力条目，不另写一套不同数值。

### 8. 种族内各派系

每个派系一份文档：

- 背景概述与一句话玩法。
- 所属种族、共享内容引用及例外。
- 地图位置、初始领土、邻居、关系、威胁与机会。
- 派系领袖及传奇人物引用。
- 派系特性：效果、作用对象、范围、原型及代价。
- 专属机制：原型与必要差异；没有独有机制也可成立。
- 专属兵种、人物、建筑、科技、能力的差异清单及引用。
- 起始军队与经营基础。
- 开局行动、中期成长与长期胜利目标。
- 与同种族派系的实际区别。

## 统一记录与引用规则

每个对象按需要记录以下信息，不重复套长表头：

| 项目 | 规则 |
| --- | --- |
| 背景依据 | 区分辐射设定、用户决定和助手架空建议 |
| 原型 | 写具体战锤对象及采用部分，不能只写“参考帝国／鼠人” |
| 改动 | 标明直接沿用、换皮、数据调整或组合现成组件及理由 |
| 设计状态 | 候选、初设、用户确认、搁置；确认注明范围 |
| 技术证据 | 未核、已定位、局部验证、目标范围已验证；引用证据和实际边界 |
| 未填项 | 写待定及原因；无此项写不适用；共享项直接引用 |
| 数值 | 优先沿用原型，需要偏离才说明理由；不伪填精确数值 |
| 唯一责任 | 同一规则或条目只在一处维护，其他地方链接引用 |

概念成立、原型存在、数据已定位、实际游戏验证通过是不同结论。

## 设计推进顺序

1. 沿用总纲、种族目录和各文档职责；有实际内容需要时调整结构并同步入口，不为每轮工作重建模板。
2. 每次选一个种族，先完成种族概述与机制原型选择，不直接从某个派系写起。
3. 补该种族共享兵表、建筑、科技、人物和能力，使基本玩法能够衔接；按依赖往返，不机械要求一份写完才能读下一份。
4. 再填写种族内各派系的定位、开局、特性与专属差异。
5. 做种族内及跨种族比较，检查重复、全能化和不必要制作成本。
6. 直接更新正式责任正文并同步导航与引用，标清候选、初设与已确认范围；仅影响方向的关键分歧向用户提问。技术验证由承担该职责的对话按授权独立推进。

对应正文就地更新，保持原型、循环、职责、差异与待定项可追踪。

## 共同约束与候选池

可玩种族须有经营、招募、作战、补员和成长的完整循环，同种族共享主体，派系通过开局与有限差异区分。普通AI保留地理和外交意义，不为每个组织另建完整文化或独立资源。

### 五、派系增多的实际设计方法

1. 优先增加同文化不同开局和普通 AI，而非每次增加一套兵表、建筑、科技和资源。
2. 通用 AI 至少有定位：守备、扩张、劫掠、缓冲或贸易。不同模板改军队倾向、初始关系与起点，不必各有专属面板。
3. 允许强弱不对称：小帮派可以弱，但应能形成地理和外交意义，而不是无限刷新经验。
4. 地图先布主战线、支线冲突和地方势力，再决定聚落密度；不靠无意义拉长行军距离扩大面积。
5. 原子神教等组织以人物、设施和事件体现特色。

### 六、原型与技术待定

C11／C12已确定共享归类；学院知识／渗透的具体宿主、义勇军代理与跨种族整合的实际权限，主教的战斗形态，铁路组织的表现，原子神教事件位置，新增 AI 数量与地图性能，均未核验。

本表先完成内容占位，不宣布全部可玩，也不进入批量资产制作。实际活跃派系数量需与回合等待、AI 行动和地图密度一起评估。

背景核对：[The Master](https://fallout.fandom.com/wiki/Master)、[Unity](https://fallout.fandom.com/wiki/Unity)。海斯、塞拉斯等原创人物为候选，须按原作优先原则比选。其他新增组别目前为身份候选，详细原作内容在具体选型时再核对；不要求其年代共存。

重点比较 NCR 与大汉帮的射击体验、军团与部落的突击体验、维加斯与大山脉的机器人体验、兄弟会与英克雷的精锐体验。差异优先由兵表职责、开局和现成效果承担。

助手直接在各责任文档中完成原型选型和内容细化；种族、派系及地图分别维护，不以追加提案代替更新正文。首版数量不由候选表自动决定。

邮差与避难所分别只在[邮差设计](邮差传奇事务官设计.md)、[避难所设计](避难所玩法初设.md)维护详细规则。避难所三类完全独立；封闭型开启后果纯随机，不预警、不保底、不按时期调整收益，也不转成其他两类。

### 7.1 单位设计口径

以下是具备战术职责的第一批单位槽位，不是按原作武器穷举。代表单位与完整兵表均在各种族的兵种设计文档维护，本节只维护共通口径。所有名称和原型均为助手设计选择，仍待目标版本数据定位与资产适配；制作状态见资产与技术记录。

阶段“初／中／高”表示玩法获得阶段，不直接等于建筑1／3／5级。每行编制、速度、质量、攻击与射击行为默认继承拟用原型，再调整必要数值；未核对前不虚填模型数。来源骨架相同但武器行为不同的单位仍要逐项适配。

同文化共用基础内容，按派系核心权限分配兵表；异形的主教、杰森与女王不默认共用完整兵表，专属单位与招募权限以条目为准。通用伤害不按“实体／能量”一刀切：激光可取魔法攻击表现，但破甲与法术来源仍独立；高斯不因是高科技自动获得魔法属性。普通低级兵在训练后仍为中后期主体，兼有守备、补充和专业用途，不仅是等高级兵解锁的过渡。

表中“限制／反制”决定需要保留的取舍，不先写最终费用与百分比；容量只用于确有理由的精锐组，不把全部文化改为同一种容量经营；高级可用训练成本、有限池或生长周期等合适约束。

### 长期基础军与高级战力的共同口径

已确认：前期以基础兵和极少开局高级兵起步；中期多支军队，升级基础兵＋少量高级兵＋大量低级兵混编，昂贵主力只能维持少数，其他军队可用廉价兵；后期经过训练的基础兵仍占主体。少数主力不是永久两军上限，不普遍降低模型数或战斗烈度。

高级战力按身份采用容量、训练成本、有限池或生长周期，选择必要的主要约束；保留建筑招募与AI可靠基础规则。战帮晋升、废料改造、工坊研究和挑战只在适合的种族配置，不要求每族四套齐全；直接招募与主动转换检查同一目标资格和供给，不以经验或合邦绕容量。基础经验和普通科技不普遍增加维护；主动高级换装支付新增训练／装备成本，不对同一许可五重收费。

### 8.1 普通领主与事务官类型

类型先围绕兵表与原型设置；不同文化可共享底层行为，名称与技能组分开。人物类型不是另一个文化，不给每个普通领主独立经济。普通事务官以少量可区分的类型为主，避免把狙击、观察、潜行拆成三套近似英雄。

事务官行动类型只按原型实际支持内容配置。上表名称不保证能刺杀、偷科技或破墙；后续技术定位后填写动作包。人物容量与招募建筑沿文化经营配置，不用传奇英雄填补普通类型缺失。

各族建筑链、层级、招募、容量及驻军在各自《建筑设计》维护，入口见[种族总览](#种族与派系入口)。沿用原版主聚落、收入、发展、治理、军事和防御结构，保留槽位取舍；不因目录统一要求所有种族具备全部类型。

基本成长采用“基础军→升级基础兵为主体、少量专业兵→基础主体继续有效、有限精锐支援”，不是后期普遍精锐满编。建筑解锁、科技强化和人物所率军队效果分开；英克雷与好好先生等专属成长例外见本族机制，不重复收取同一许可。

### 8.4 科技树首批节点主题

每个箭头表示一条三节点分支的初设前置，共四条分支、十二个主题节点；只是第一层可审阅研究结构，不宣称是最终完整科技数量。各节点作用范围固定到指定单位组或经营类别，研究时间与数值待游戏数据与成长节奏确定。普通节点不新增研究资源。

## 特色机制与目标入口

详细跨族原型比较唯一维护于[目录驱动的组合选取](#目录驱动的种族与重点派系组合选取)及其异形深比较；各族机制和派系目标仍由种族正文唯一维护，见[种族总览](#种族与派系入口)。以下保留商路、非征服组织及共通接口；候选不代表可移植或已实现。

### 9.8 商路与非征服组织

商路先交给商贸城邦／商队公司作为机制候选，而非把豪斯、好好先生强制改成商队派系。玩家是否可直接操控该集团，留待其基础兵表与经营完整度确定；AI商队能力不能仅凭玩家原型存在来推定。暂不为只出现于事件的商人开发完整可操作商队。

天启追随者以医疗／研究事务官、地方设施与任务体现；原子神教以辐射地点、地标和事件体现；铁路组织现归C12，安全屋／有限救援及人员身份由对应种族正文维护；不为天启和原子神教强造全国兵表。中国背景内容仅按[素材储备文档](./素材储备/中国背景素材.md)保留准备材料，本节不恢复其派系资格。

### 地方占领者、准备与连续战争需求

世界上的城镇需要掠夺者、独立聚落、地方守备、机器或生物巢穴等实际占领者，不全空城，也不全主动扩张。种族AI按可靠基础招募、守备和恢复规则行动；弱帮派与小据点支持局部积累，地区重镇有独立驻军，核心城与主力合防更难攻。重要城市主力战败后仍有防御与恢复时间，不一路空城，但不增加复杂物流。

攻坚准备可选择伏击、事务官、仪式、围困或外交等合适组合，不每战强制完整连招。工事、射界、通道与预备队承担攻城难度，重镇与主力防城需围困削弱，双方有压力、出击和援军有价值，不靠安全等待必胜或普遍延长战斗。每座小城不做堡垒；空间与场景由世界／战斗责任正文落实。

外交根据威胁和利益回应扩张，近邻更敏感、缓冲区有价值，适用于AI强国而非全图无条件反玩家；正常合作与盟友安全应有收益。各族目标继续支持局部胜利积累、战略胜利准备和连续战争消耗，不改变大地图多势力方向。本节是对种族开局、目标与AI的需求，不另建一套外交或攻城系统。

### 异形周期、风暴与待考察原型

肉食、四阶段、即时部分招募与留猎只在[异形机制](./种族/异形/种族机制.md)维护。风暴空间与防护范围归世界，单位损耗豁免、短期强化及失控标签归战斗；异形建筑免损待确认。

培养缸、实验室与巨釜的有限用途见[原型比较](#异形四阶段与培养缸血肉实验室巨釜的深比较)，均非默认新增系统。

### 9.9 本节选型依据

混沌矮人官方介绍支持把锻炉强化、政治席位、商队分开观察，但不证明跨文化移植。[SEGA介绍](https://sega.prezly.com/total-war-warhammer-iii-the-forge-of-the-chaos-dwarfs-is-out-now)

### 10.5 胜利条件工作稿

胜利继续沿用原版任务与战役目标形式，可完成后继续游玩。下表为主题目标组合，不锁定具体城镇数或战斗数；不同领主在共同文化目标上改指定地区和敌人，避免全员统一“占领胡佛水坝”。

后期危机暂不独立制作一套新系统；保留原版结构与已选势力的后续内容入口。凯撒和主教不因强大就同时自动变成所有派系的末日敌人。
