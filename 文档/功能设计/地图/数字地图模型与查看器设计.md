# 数字地图模型与查看器设计

更新日期：2026-11-10。状态：六边形模型、河流／桥梁表达和首版查看范围已确认；数据字段与示例参数为助手初设，实施进展在第八节维护。游戏地图制作链另行验证。

本文维护地图规划工具的数据模型与交互范围。玩法目的、布局理由及约束由[战役地图设计](./战役地图设计.md)维护；已数字化区域的空间位置、辖区、初始归属和通路以地图JSON为唯一维护源，正文引用其稳定ID。尚未数字化的区域继续从战役正文接续，迁入时同步原表与引用。

## 一、目的与范围

采用离散六边形地块，规划空间拓扑、地形、地表要素和通行规则。初期使用整数网格坐标，专注于区域布局、通路、屏障与附着物设计；比例、连续地表已作为规划数据填充，游戏实际坐标在后续制作阶段处理。

地图模型使用JSON，原生HTML、JavaScript与SVG提供可视化查看。首版覆盖多文件加载、区域切换、拖动缩放、图层筛选、按ID／名称定位及属性查看。地图内容通过修改JSON维护，后续沿同一模型扩展可视化编辑。

## 二、世界与区域

世界由多个区域地图组成，例如主战场各编辑分区、大山脉和马德雷。大地图沿山脉、峡谷、河流等空间边界拆分，保留通路端点，支持逐区推进。编辑分区沿用已有规划区R、行省P、城镇辖区及派系F编号作为内容引用，各分区自身另有地图ID。

| 层级 | 唯一维护内容 |
| --- | --- |
| 世界索引 | 区域地图ID、名称、文件位置与设计状态；通路配对（含合并后同区域的远距节点）；跨区域共用的规划区、行省、城镇辖区名称及初始归属元数据 |
| 区域地图 | 本地六边形地块、特殊共享接边、地表对象的位置，以及对公共分组的引用 |
| 战役设计正文 | 区域玩法目的、派系需求、叙事、布局理由及待定事项 |

区域地图是编辑分区，与规划区、行省可以交叉。地块只引用城镇辖区ID，再从公共元数据取得行省、规划区和初始派系，层级关系只维护一次。城镇对象记录实际位置，初始归属从其辖区读取；后续领土变化由游戏实现承载。

未展开区域可先在世界索引登记名称与设计状态，保留未配置端点。已经数字化的区域在数据中记录设计状态及正文来源。主界面显示地图名称、ID、加载状态和实际通行条件；图例位于地图左下角，可展开或隐藏。

## 三、地块与坐标

采用尖顶六边形与轴向整数坐标q、r，固定六方向为东、东北、西北、西、西南、东南。地块局部ID由q、r确定，完整身份由地图ID与局部ID共同确定；显示像素坐标由查看器计算。地表对象的位置使用地块引用，移动对象保持其内容ID。

地块维护：

- 坐标及由坐标确定的局部ID。
- 地形，例如荒漠、草原、山地、水体、城市废墟。
- 规划环境属性，例如辐射初值。
- 城镇辖区ID。

地表对象在区域对象表中保存一次，记录稳定ID、类型与所在地图／地块；查看器从对象表生成地块详情。一个地块可承载多个兼容对象，例如城镇、地标和任务标记。普通建筑规则引用种族正文，地图只记录影响空间设计的设施。

地块的六方向几何相邻由坐标确定。实际通行读取共享接边，地块自身不另存通行开关。山地、河流、桥梁和大型水体的通路均由接边表达。

## 四、共享接边、河流与桥梁

### 接边身份与默认值

接边只连接同地图内几何相邻的两个已存在地块。两端排序后确定唯一身份，两侧读取同一条记录。

普通相邻地块的默认边为开放、陆地边界、无特殊设施、移动代价1、无额外效果；JSON只保存特殊接边。地图外方向没有可到达地块。水体地块与每个已存在邻格之间的接边须显式配置；无邻格的方向显示地图外。六方向均有明确结果，完整表达水面边界与桥梁通路。

| 属性 | 内容 |
| --- | --- |
| 两端 | 相邻地块的局部ID |
| 状态 | 开放／关闭 |
| 边界地貌 | 陆地、水体、山体等 |
| 通行设施 | 无、道路、桥梁、渡口等 |
| 移动代价 | 抽象规划值，普通边默认1 |
| 通过效果 | 可选效果说明，例如穿越损耗；引用已有玩法规则 |

边界地貌与通行设施分别配置，水体与桥梁可存在于同一接边。代价是本次跨边的总规划成本。地块环境影响与跨边效果分别注明来源及对象，后续映射时按来源核对结算。

### 小型河流

小型河流以连续的水体接边表达，两岸仍是陆地地块。涉水边可开放，并配置高于普通边的移动代价；例如普通边1、涉水边2均为助手示例值。

连续水体接边之间的一段可设置桥梁：该边保留水体地貌，通行设施设为桥梁，状态开放，代价采用桥梁配置。查看器将水线连续绘制，并在该段显示桥梁穿越，形成沿河寻找桥梁或付代价涉水的空间选择。

### 大型水体与大型桥梁

大型河道、湖泊等直接使用水体地块。普通水面地块的各水体接边按实际设计关闭；有明确通路时单独开放相应边。

大型桥梁可跨越一个水体地块：该格东北、西北、西南、东南四边为关闭的水体接边，东、西两边为开放的道路／桥梁通路。地块表面显示连接东西两侧的桥面，两岸军队沿两条开放边通过该水体格。其他朝向可依六方向旋转，连续桥面可由多个水体地块接续表达。

桥面显示根据两侧开放设施边生成，通行仍读取接边。首版示例同时覆盖小河涉水、小河桥梁和大型水体桥梁。

### 显示约定

水体边沿六边形共享边绘制；道路显示连接相邻格中心的行进方向；小河桥梁在水线穿越处显示桥面，大型桥梁在水体格内部显示连接两侧通路的桥面。普通开放边弱化，关闭边、河流和桥梁突出；颜色与线型共同区分状态。

## 五、通路地块与跨地图交互

普通出口与特殊入口都由通路地块及地表入口对象表达。军队先沿本地图接边到达通路地块，再按跨地图记录连接另一端。普通出口承接连续行军，文件切换本身不额外产生代价；特殊入口沿既有剧情及派系规则。

每条通路在世界索引保存一份记录；两端可以在不同区域，也可以是同一区域内有连续地块路径的道路端点，两端仅引用通路ID：

| 字段 | 内容 |
| --- | --- |
| 通路ID与名称 | 稳定标识及显示名称 |
| 两端 | 各自的地图ID与地块ID |
| 类型 | 普通通路／特殊入口 |
| 方向 | 双向或单向的拓扑关系 |
| 代价与效果 | 规划中的跨区行军或交互代价，只在通路记录维护一次 |
| 使用条件 | 分方向、行动者及剧情状态填写说明，并引用现有责任正文 |
| 配置状态 | 完整、端点待定或区域未展开 |

大山脉的条件分别表达外来军进入／撤回、本地势力统一前限制、本地玩家统一开放及杰森剧情破障。查看器展示实际通行条件，条件来源保存在数据中；首版不执行战役条件或模拟动态剧情。大山脉与马德雷的地理相邻、各自围合及各自入口规则保持。

端点允许明确标为待定。已配置目标若尚未加载，显示“区域未加载”；目标区域已加载却找不到所指地块，报告引用错误。

## 六、JSON组织与维护

首版契约为`schema_version: 1`，文件使用UTF-8。世界索引见[世界索引.json](../../../content/world/世界索引.json)，区域文件见其中`maps[].file`。公共分组内嵌世界索引，区域只引用ID。

| 文件／字段 | 具体契约 |
| --- | --- |
| 共通 | `schema_version`为1；`kind`为`world`或`region`；`id`为非空字符串 |
| 世界 | `name`、`status`、`note`说明用途和覆盖边界；`maps`、`routes`为数组，`groups`为公共分组对象 |
| `groups.regions`／`factions` | 以R或实际派系实例ID作键，值包含`name`。固定地方守军可使用明确的描述性身份作为键 |
| `groups.provinces` | P编号作键，值为`name`与`region`引用 |
| `groups.towns` | 既有城镇辖区ID作键，值为`name`、`province`、`faction`。归属仅在此保存；不把编辑分区当行政区 |
| `maps[]` | `id`、`name`、相对世界索引目录的`file`、`status`；`sample`为样本，`unexpanded`为未展开。未展开文件可以尚不存在，查看器不会自动读取文件或造地图 |
| 区域 | `name`、`status`、`source`、`note`及`tiles`、`edges`、`objects`数组；`status`与`source`保留设计身份和正文依据，界面不展示这类说明元数据 |
| `tiles[]` | `id`严格为`q,r`（例`2,-1`），整数`q`、`r`；`terrain`为`desert / grassland / mountain / water / ruins`；`jurisdiction`为辖区ID或`null`；`radiation`为非负数或`null`（待定）；可附`note` |
| `edges[]` | `a`、`b`为同区域已有且几何相邻的地块ID；两端排序后的组合唯一，不另存第二份边ID。`state: open / closed`，`landform: land / water / mountain`，`facility: none / road / bridge / ford`，非负数`cost`，字符串数组`effects` |
| `objects[]` | 全世界唯一`id`，`type: town / landmark / task / portal`，`tile`；城镇只保存这三项，名称统一读取`groups.towns[id].name`。地标／任务／入口另有自身`name`及可选`note`；`portal`须有`route`引用且位置匹配通路某端；`town`的ID须与所在辖区一致 |
| `routes[]` | 唯一`id`、`name`，`type: ordinary / special`，`a`、`b`各为`{map,tile}`或`null`，`direction: both / a_to_b / b_to_a`，`cost`为非负数或`null`（待定），`effects`与`conditions`为字符串数组，`source`为正文依据，`status: complete / pending / unexpanded`；同区普通道路附`path: {map,tiles}`，tiles按实际相邻地块顺序保存 |

六方向顺序固定为东`(1,0)`、东北`(1,-1)`、西北`(0,-1)`、西`(-1,0)`、西南`(-1,1)`、东南`(0,1)`；尖顶格中心像素由`x=√3·size·(q+r/2)`、`y=1.5·size·r`计算。未保存的已有陆地邻接按第四节默认值处理；水体地块到已有邻格必须显式配置。无邻格方向显示地图外不可达。

加载通过浏览器文件选择读取，支持世界／区域任意顺序及分批补选；重复世界索引或地图ID逐一确认后替换，取消则保留已有版本。不会据`file`路径自动访问磁盘。非法JSON／格式版本拒绝加载并报告文件名；结构、重复ID、辖区、接边和通路引用错误集中显示，错误区域不绘制为有效地图。端点`null`、未展开和已配置但未加载分别提示；目标已加载却缺地块报告错误。跨区代价`null`显示待定，跳转只改变查看位置。

首版不提供写回、导出或模型迁移；内容仍由手工编辑JSON维护。字段契约和校验是规划工具约定，尚未映射游戏数据库。

## 七、首版HTML查看器

### 布局

| 区域 | 功能 |
| --- | --- |
| 顶部简栏 | 多选加载JSON、地图名称、按ID／名称搜索、重置视图 |
| 左侧 | 区域切换、图层开关、要素筛选 |
| 中央 | 六边形地图、拖动平移、滚轮缩放、点击选择；左下角叠加可展开／收起的图例 |
| 右侧 | 地块属性、公共辖区归属、地表对象及六方向共享接边详情 |

图层控制地形底色、辖区边界、接边、地表要素与名称标签。筛选可突出城镇、特殊入口或指定行省，其他地块淡化以保持空间参照。

点选地块后高亮本格与几何邻格，开放／关闭边使用不同样式。右侧六方向显示相邻地块、有效默认值或特殊边配置；悬停详情行时高亮对应边。不存在相邻格的方向明确显示地图外。

通路对象显示另一端与使用条件；目标已加载时可切换地图并选中对应地块，未加载时提示补选文件。搜索支持地块、城镇、地标、行省和入口ID／名称，结果定位到实际地图与对象。加载问题集中显示，并保留设计待定状态。

后续可沿同一模型添加地形画笔、接边修改、对象移动和JSON导出。

## 八、实施与交付

### 责任与目录

由“世界与战役设计”对话负责本首版工具及示例内容，整体工程对话协调、复核与维护共享状态。该职责包含此次用户指定的查看器实现；相关游戏制作工具与技术验证仍按原职责接续。

查看器源码放scripts/map_viewer/，正式地图规划JSON放content/world/，截图、临时导出与协调证据放work/。现有content/prototype/场景.json和游戏地图制作脚本保持原输入；后续按稳定ID与坐标转换接入规划模型。

### 首版内容

交付可直接打开的HTML查看器、一份世界索引及可多选加载的区域JSON。已从四省前线扩展到全图重要节点骨架，按莫哈维、南北扩展及封闭地区划分编辑分区；具体城镇和归属沿现有战役正文，网格位置及代价标明助手初设。

示例覆盖普通边、关闭边、小河涉水、小河桥梁、大型水体桥梁、普通跨区连接、特殊入口；实际未定参数以null保留。完整城镇数量和游戏行军距离后续随真实地图制作收敛。

### 当前进展与边界

实际入口：[scripts/map_viewer/index.html](../../../scripts/map_viewer/index.html)，同目录加载[viewer.js](../../../scripts/map_viewer/viewer.js)和[viewer.css](../../../scripts/map_viewer/viewer.css)。双击HTML，点击“加载／补选JSON”，多选`content/world`中的五份JSON；文件选择器中可用Ctrl多选，也可分批加载。

已实现源码：区域切换、拖动／方向键平移、滚轮／按钮缩放、居中、地形／辖区／接边／对象／名称图层、行省及对象类型突出筛选、ID／名称搜索定位、地块及六方向详情、边行悬停／聚焦高亮、分方向通路跳转与条件展示。文件中的文本以文本节点显示；查看器不执行行军、外交、剧情或费用结算。

区域文件以[世界索引](../../../content/world/世界索引.json)的maps清单为准；当前4个区域共656地块、146对象、17通路，含85个城镇对象。

- [莫哈维与西北](../../../content/world/莫哈维主体.json)：门户、都市、中北生态、河岸两线、军团纵深及西北英克雷基地。
- [北方峡谷与草原](../../../content/world/北侧接续.json)：锡安诸部落、大汉主部及南东商路。
- [远东北工业废墟](../../../content/world/东北工业.json)：学院、铁路安全屋、义勇军、芳邻镇及地方工业聚落。
- [南部荒野与封闭地区](../../../content/world/南部荒野.json)：女王与荒野落脚点、大分水岭四城链、大山脉盆地及马德雷。文件合并不改变各自围合与特殊入口。

城镇名称与初始归属唯一维护于公共分组，城镇对象只保存ID、类型与位置。新增节点按已有主通路连接，其他几何邻接显式关闭；跨分区与特殊通路在世界索引维护，同区普通通路另有path记录连续地块路径。区域轮廓沿城镇和主路展开，莫哈维299格、北方79格、远东北76格、南部202格。莫哈维压缩西北基地与河岸之间的空地，都市与河岸之间保留接应空间；北方草原与峡谷分段，远东北采用更密集的旧城、科研和住区路网。南部沿东西干线展开，深南峡谷及东南封闭区保留分岔与围合。河道仅开放大坝、南湾两处桥面，陆侧支流保留涉水和小桥。地表形状、道路宽度、真实距离及控制区仍需细化，不代表游戏可运行地图；同辖区附属地标不额外授予建筑格、招募或能力。参考来源及架空落点对应见战役正文6.2节。

源码、JSON与引用已完成静态自检。用户已手工打开页面并反馈界面调整；完整数据加载、河桥显示、跨区跳转及其他交互尚未形成运行验收记录。查看器无新增依赖，游戏地图转换、实际开局与部署仍按技术职责接续。

下一步可由用户手工打开检查文件选择、桥面水线、切区及错误提示；游戏地图导出链仍需另行明确网格比例、连续地形、高程与通行数据映射。
