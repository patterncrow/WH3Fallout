# 数字地图模型与查看器设计

更新日期：2026-11-10。状态：抽象模型与首版功能范围已确认；技术选型为实现建议，尚未制作或验证。

本文维护地图规划工具的数据模型与交互范围。战役内容、地区布局、城镇与派系位置由[战役地图设计](./战役地图设计.md)维护；工具读取或承载这些内容，沿用已有稳定ID。

## 一、目的与范围

采用离散六边形地块，规划空间拓扑、地形、地表要素和通行规则。初期使用整数网格坐标，专注于区域布局、通路、屏障与附着物设计；比例、连续地形及游戏实际坐标在后续制作阶段处理。

地图模型使用JSON，HTML提供基本可视化查看。首版覆盖加载、切换区域、拖动缩放、筛选和属性查看；地图内容可先通过修改JSON维护，可视化编辑作为后续扩展。

## 二、世界与区域

世界由多个独立区域地图组成，例如主战场各区域、大山脉和马德雷。大地图可沿山脉、峡谷、河流等空间边界拆分，预留若干通路地块，支持逐区推进。

世界索引维护区域清单及跨地图通路；每张区域地图独立保存JSON，维护本区域的地块、接边与地表内容。各区域属于同一世界，已有规划区R、行省P、城镇辖区与派系F编号继续使用。

| 层级 | 唯一维护内容 |
| --- | --- |
| 世界索引 | 区域地图ID、名称、文件位置、设计状态，以及跨地图通路配对 |
| 区域地图 | 六边形地块排列、地块属性、共享接边、地表对象与本区分组归属 |
| 战役设计正文 | 区域的玩法目的、派系规则、叙事、设计理由及待定事项 |

区域地图是编辑分区，不要求与规划区、行省一一对应。地图文件位置可以调整，对象关系依靠稳定ID保存。

## 三、地块

一个六边形定义为一个地块。使用整数网格坐标表示位置，具体坐标编码由实现选型确定。六边形排列自动确定几何相邻关系。

地块维护：

- 唯一编号与网格坐标。
- 地形，例如荒漠、草原、山地、水域、城市废墟。
- 环境属性，例如辐射。
- 城镇辖区归属；辖区再关联行省和规划区。
- 地表对象，例如城镇、建筑、地标、任务点或通路入口。

地块不另设通行属性，相邻地块之间的通行统一由共享接边决定。山地的通路可通过关闭部分接边、开放山口方向表达。

地表对象拥有稳定ID，并记录所在地图与地块。一个地块可以承载多个兼容对象，例如城镇、地标和任务标记。初期建筑内容以影响空间设计的设施为主，普通建筑规则引用种族正文。

## 四、共享接边

接边仅描述几何相邻地块之间的边界属性。相邻两格共用同一条边，数据保存一次；从任一地块查看或修改时均指向该记录。

| 属性 | 内容 |
| --- | --- |
| 两端 | 相邻地块ID |
| 状态 | 开放／关闭 |
| 类型 | 普通、道路、河流、桥梁、渡口等 |
| 通过代价 | 可选，使用抽象行动成本 |
| 通过效果 | 可选，例如损耗 |

状态、类型、代价与效果可以组合。例如桥梁可开放且具有通行成本；辐射山口可开放，同时具有较高成本和穿越损耗。地块环境与穿越接边的效果分别记录其作用对象，避免同一来源重复结算。

河流、桥梁等边界要素附着于接边，连续道路或河流可由多条接边构成。接边不承担非相邻地块之间的连接。

## 五、通路地块与跨地图交互

普通出口与传送门均以特殊通路地块表达。普通出口可表现为山口、公路、隧道等；传送门等特殊入口按各自规则配置交互条件。

军队沿本地图接边到达通路地块，再执行跨地图交互。跨地图配对属于通路地块的交互关系，与六边形接边分别维护。

每条跨地图通路在世界索引保存一份配对记录，两端地块引用其ID：

| 字段 | 内容 |
| --- | --- |
| 通路ID与名称 | 稳定标识及显示名称 |
| 端点一 | 地图ID、地块ID |
| 端点二 | 地图ID、地块ID |
| 类型 | 普通通路／特殊入口 |
| 方向 | 双向或单向 |
| 条件 | 按设计需要填写开放条件 |

未设计的区域可以先登记名称与设计状态，并预留出口；目标端点允许标为待定，查看器清楚显示其未配置状态。

大山脉与马德雷可保持地理相邻、各自围合并经各自入口出入。地理位置、当地六边形接边和跨区域入口各表达对应的设计事实。

## 六、JSON组织与维护

采用一份世界索引及每区域一份JSON。JSON内部按地块、接边、对象与分组组织，保持可阅读和可手工编辑。

- 地图ID在世界内唯一，地块可采用地图ID与本地编号组合。
- 接边由两端地块确定唯一身份，避免两端各存一份相反属性。
- 城镇、地标等沿用现有内容ID，位置变化仅调整所属地图和地块。
- 世界索引是跨地图通路配对的唯一数据源，两端地块仅引用通路ID。
- 图形位置与通行规则由同一模型读取；示例数据、助手初设和已确认内容明确标识。

当前选用JSON。后续如有实际的大量局部写入或复杂查询需求，再评估存储调整；稳定ID及对象关联继续保留。

## 七、首版HTML查看器

### 布局

| 区域 | 功能 |
| --- | --- |
| 顶部简栏 | 加载JSON、显示地图名称、重置视图 |
| 左侧 | 区域切换、图层开关、要素筛选、图例 |
| 中央 | 六边形地图、拖动平移、滚轮缩放、点击选择 |
| 右侧 | 当前地块属性、地表内容及六条接边详情 |

### 图层与筛选

图层控制地形底色、辖区边界、接边、地表要素与名称标签的显示。筛选用于突出特定类型或归属，例如城镇、传送门、指定行省；其他地块淡化，保持空间参照。

### 点选与详情

选中地块后描边高亮，邻接地块轻微高亮。右侧显示基本属性、归属和地表对象，并按六个方向列出邻接地块及共享接边属性。指向接边详情行时，高亮地图上的对应边。

普通开放边弱化显示，关闭边及河流、桥梁等特殊边突出显示。通路地块可查看另一端；目标已加载或可取得时，切换地图并选中目标地块。待定端点显示明确状态。

### 实现建议与后续扩展

首版优先采用原生HTML、JavaScript与SVG，按实际需要选择最少依赖。通过文件选择加载JSON，具体多文件加载方式由实现确定，兼顾直接打开HTML的使用方式。

后续可沿同一模型添加地块属性修改、地形画笔、接边切换和JSON导出。当前阶段不要求建设数据库、地理投影或完整GIS编辑系统。

## 八、实际实施的交付边界

后续实施应交付基本HTML查看器、世界索引与可加载的区域JSON示例。示例应覆盖普通接边、关闭边、桥梁或损耗边，以及普通跨区通路和传送门；实际区域内容以战役设计为依据，示例身份清楚标注。

将模型用于真实游戏地图时，再明确网格比例、区域拼接、连续地形、地形高程与游戏通行数据的制作方式。规划模型与查看器可用，不代表战锤地图导出链已通过。

项目规则、实现职责、导航登记及后续执行安排由主对话结合现有工程框架落实；本设计文档不授权运行构建、测试、游戏、提交或推送。
