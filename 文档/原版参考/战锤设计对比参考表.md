# 战锤设计对比参考表

版本：参考基线0.7（2026-11-03工程治理，不改变选型）。**本表是本项目最主要的设计对照依据。**项目原则以[项目概念设计](../../项目概念设计.md)为准。

## 一、如何使用与区分状态

从战锤既有设计出发，先选择原型，再给出辐射身份。每项区分：

- **沿用**：保留玩法，主要换名称、模型、图标、文本和声音；不另造系统。
- **重点适配**：用户关注的核心方向，需要具体原版选型与必要规则设计。
- **可选特色**：只供有需要的文化、派系或人物选择，不作为标配。
- **不采用／暂缓**：用户排除或暂不考虑的内容。
- **待定**：方向尚未决定。

所有“采用”均为设计状态，不是实现成功。本体与参考DLC的来源及版本见资源与环境准备，实际数据定位与局部验证范围见技术概要和工程状态；本表不维护第二份技术通过清单，也不能由局部结果推定全部实例、数值和跨文化移植成立。通用规则直接沿用；下面完整列出是为了防漏，不代表每格都需专门开发。

### 五、伤害与防护必须分开建模

基础伤害／破甲伤害决定装甲处理；物理或魔法攻击影响相应抗性处理；火焰属性与法术来源另有规则。它们不是互斥的一列伤害类型。

魔法攻击不自动绕过装甲，法术抗性也不等同于抵抗所有带魔法属性的武器。魔屏是另一种保护机制，不能只按名称解释成防激光装甲。具体公式和数值以后按目标版本核对。[官方伤害说明](https://community.creative-assembly.com/total-war/total-war-warhammer/blogs/6-feature-focus-2-damage-part-1)

| 项目 | 原版参考作用 | 应检查 |
| --- | --- | --- |

| 专业兵 | 承担特定职责 | 有适用场景，也有短板 |

建筑层级、科技、单位经验、人物军队加成是不同成长路径，不能把它们都称为兵种升级。

| 刺客／潜行者 | 机动、潜行和猎杀 | 刺杀、伤害或阻碍等 |
| 混合型／特殊英雄 | 多种职责组合 | 按该类型实际权限登记 |

这些不是可自由赋予任何英雄的固定行动包。专业名称不能自动证明拥有某项行动。

### 四、领主技能树的设计层

| 分支或节点 | 常见作用 | 需要检查 |
| --- | --- | --- |
| 战役线，常称蓝线 | 移动、补员、招募、维护、损耗、战后收益等 | 每项作用范围与实际类型，不假定一套蓝线适用所有人 |
| 军队线，常称红线 | 强化指定兵种组或军队能力 | 单位集合是否覆盖新兵表，经验条件与分支选择 |
| 个人战斗线，常称黄线 | 攻防、生命、伤害、射击等 | 与人物动作及定位匹配 |
| 法术线 | 解锁法术、强化施法与资源利用 | 法术派系、升级、过载及附带效果 |
| 独特线 | 人物身份、指定部队或特殊能力 | 是否与派系特性重复，是否改变玩法 |
| 坐骑与形态 | 战场机动、攻击与生存改变 | 实际获取方式、模型、动作与切换限制 |
| 关键独立节点 | 不朽、能力或专门被动等 | 等级、前置、类型和版本差异 |

颜色是便于交流的常见称呼，不是所有人物技能树都严格具有同样颜色和分支。

### 五、事务官技能树的设计层

| 分支 | 作用 | 应与什么对应 |
| --- | --- | --- |
| 战斗成长 | 近战、射击、装甲、生存等 | 实际人物原型 |
| 法术成长 | 法术与施法支援 | 施法类型与法术派系 |
| 战役行动强化 | 成功率、成本及相关效果 | 该英雄实际拥有的行动 |
| 嵌入军队强化 | 训练、补员或其他支援 | 明确的军队范围与叠加规则 |
| 地区被动强化 | 收入、秩序、腐蚀或净化等 | 所在区域的实际作用范围 |
| 专属与解锁 | 坐骑、独特能力或传奇效果 | 前置、独有性和生命周期 |

不默认事务官具有完整的领主红线，也不因加入军队就自动获得统军权限。

### 六、技能节点规则

| 检查项 | 记录内容 |
| --- | --- |
| 入口条件 | 人物类型、等级、前置节点与前置投入 |
| 投点 | 节点等级数、每级效果、点数来源及是否自动解锁 |
| 分支结构 | 串联、并列、门槛、互斥和终点节点 |
| 作用对象 | 仅本人、所率军队、嵌入军队、地区、派系或指定单位组 |
| 效果形式 | 数值、被动、主动、招募权限、法术或坐骑 |
| 持续与叠加 | 永久、条件生效、同类是否叠加、失效条件 |
| 配军关系 | 是否漏掉新单位，是否误加成共享原型或敌方单位 |
| AI | 自动加点的选择与必要节点可达性 |
| 重置 | 目标版本是否支持、成本与状态处理，不能默认无限免费重置 |

### 七、特性、装备与技能分开

- 派系特性：派系级身份及效果。
- 领主／人物初始特性：选定人物或招募候选的差异；游戏内表现与底层实现另行核对。
- 后天特性：战斗、行动、地区经历或其他条件获得的变化。
- 击败特定领主奖励等：获得条件、作用与版本需单独记录。
- 技能：等级与投入形成的成长结构。
- 装备与随从：可装备或分配对象，存在槽位与适用限制。

装备参考检查：武器、防具、护符、附魔物品、奥术物品、旗帜及随从等实际类别；稀有度、获取、专属条件、主动能力、重复、合成或处理方式。并非每个人物都能使用所有槽位。

坐骑不只改变外观，可能改变体型、速度、动作、目标受击面积及技能表现。用坐骑表达载具需要单独确认，不能按名称直接替换。

### 八、事务官行动与被动参考

候选行动维度：侦察与视野、伤害或刺杀人物、阻碍军队、袭击部队、破坏建筑、防御相关行动、技术相关行动、地方秩序及腐蚀相关影响。

每个实际类型分别填：主动行动／地区被动／嵌入效果／不具备；并记录目标、成本、成功与暴露、失败、冷却、经验和 AI。

不能把“破坏防御”泛化为炸毁任意场景建筑或强制野战；战役效果和战斗地图变化是不同能力。

### 九、人物完整生命周期

获取或招募 → 初始状态 → 带军／嵌入／独立行动 → 经验与加点 → 装备坐骑 → 受伤或死亡 → 返回或永久失去。

需覆盖：容量、候选池与刷新、任务解锁、唯一性、替换与解散、重招、忠诚或其他文化例外、合邦后归属、派系灭亡与返回位置、保存载入。

### 十、派系人物设计交付表

邮差的 SPECIAL、有限 Trait／Perk、互斥武器流派、专属装备与队友随从已另列[人物初设](../功能设计/邮差传奇事务官设计.md)。这是传奇事务官的内容组织，不改变本参考中的英雄统军边界，也不要求其他英雄全部采用 SPECIAL。

每个文化分别登记普通领主类型、普通事务官类型、传奇领主与传奇英雄；每类型关联技能树、行动包、招募条件、坐骑、装备范围和原型。

每个传奇人物同时检查：派系特性、个人特性、技能、任务、装备五个位置是否重复堆叠同一加成。

官方早期资料解释了人物参与战斗、英雄战役活动和独特成长的设计思想，但包含未延续的早期设想，本稿不采用其中等级、槽位或总督等说法作为战锤3规则。[早期英雄说明](https://wiki.totalwar.com/w/How_Heroes_Work)、[早期领主说明](https://wiki.totalwar.com/w/How_Lords_Work)


## 附录C：科技、建筑与经营

### 一、科技系统的设计维度

| 维度 | 原版中需要观察的内容 | 派系设计需要回答 |
| --- | --- | --- |
| 研究主体 | 通常以派系推进，部分文化有特殊形式 | 谁共享进度，是否需要文化例外 |
| 树结构 | 线性、分支、分组、门槛和多主题组合 | 玩家是否有研究顺序选择 |
| 入口条件 | 前置科技、建筑或特定文化条件 | 开局能研究什么，扩张后解锁什么 |
| 成本与时间 | 研究时间、研究速度及某些文化的特殊支付 | 谁决定研究节奏，是否容易停滞 |
| 解锁内容 | 单位、建筑、能力或文化权限等特定实现 | 哪些是必要前提，哪些是奖励 |
| 效果范围 | 派系、军队、地区、单位集合等 | 是否正确命中新兵表和建筑 |
| 分支联系 | 军事与经营、普通与高级节点的关系 | 是否存在永远最优的一条路线 |
| 反馈 | 名称、描述、图标、进度和前置提示 | 玩家能否理解为何无法研究 |
| AI | 研究选择与关键路线 | 是否能达到必要发展条件 |

不是每文化都存在表中全部特殊条件；设计前先找具体原版实例。

### 二、科技效果分类参考

| 分类 | 常见设计作用 |
| --- | --- |
| 单位战斗 | 攻防、领导力、生命、伤害、射击、装甲等指定强化 |
| 招募 | 招募费、时间、等级、条件、容量或招募效率 |
| 维持与恢复 | 维护费、补员及相应限制 |
| 建设 | 建造费用、时间、发展与建筑收益 |
| 财政 | 收入、税收、贸易及资源收益 |
| 地区治理 | 秩序、腐蚀或净化等区域规则 |
| 人物 | 招募等级、容量、行动或其他特定效果 |
| 战役行动 | 移动、损耗、战后收益与适用军队效果 |
| 政治 | 外交倾向或文化内部规则，依具体机制 |
| 专属机制 | 特殊资源、权限或文化能力，逐项核验 |

研究完成后获得加成，与单位直接变成另一兵种不同。提升招募等级也不等于提高已有单位经验。

### 三、科技树组织参考

- 常规军事与经营分支：便于玩家在战争与发展间选择。
- 单位组专题：按步兵、远程、骑兵、炮兵等组织，需覆盖该文化实际兵表。
- 建筑或设施关联：建立领土经营与研究的联系，必须确认对应原型条件。
- 政治、仪式、资源或任务关联：仅在相关文化存在合适机制时参考。
- 额外研究成本或多套成长轨道：作为专属参考，不把其任意组合视为通用能力。

具体科技卡记录：前置、时间、额外成本、效果对象、效果值、图标、文本、AI 选择与版本来源。

### 四、建筑类别

| 类别 | 主要作用 | 需要检查 |
| --- | --- | --- |
| 主聚落链 | 聚落层级、基础能力与槽位等 | 升级前提、等级上限和占领变化 |
| 基础军事链 | 常规部队与初级人物 | 初期可达性与地方重复建设价值 |
| 高级军事链 | 精锐、专业部队与高级人物 | 主城／等级限制、额外前提 |
| 军事支援链 | 招募等级、容量或其他支援 | 是地方还是全局，是否叠加 |
| 收入链 | 提供稳定经营收益 | 投入回收、共享收益与替代选择 |
| 发展链 | 加快聚落成长 | 前期价值、后期用途与替换需求 |
| 治理链 | 秩序、净化或相关地区效果 | 风险与机会成本 |
| 防御链 | 驻军、设施及战斗类型相关规则 | 建筑、地图与驻军分别核对，不假定升级必有城墙 |
| 资源链 | 特定地区生产与贸易 | 地区限制、贸易与派系内用途 |
| 地标 | 唯一地点的特殊价值 | 限定文化、层级、收益和争夺价值 |
| 文化专属链 | 特殊资源、机制或基础设施 | 是否适合移植、AI 是否理解 |

建筑数据参考字段：位置限制、等级链、成本、时间、前置、效果、招募对象、驻军、图标、模型、被占领或摧毁后的行为。

### 五、领土与省份经营

| 项目 | 检查内容 |
| --- | --- |
| 聚落与省份 | 区域归属、主城和小城、槽位、层级、特殊位置 |
| 发展 | 增长来源、积累、升级消耗、地区与省份作用范围 |
| 秩序 | 收支因素、阈值、叛乱及文化例外 |
| 腐蚀 | 类型、增长、影响、移除、文化关系 |
| 环境 | 气候、地形、损耗、通行和适应性，区别战役与战场 |
| 税与收入 | 免税、收入类别、维护成本及相关效果 |
| 行省法令 | 控制条件、选项、范围和更换 |
| 驻军 | 来源、组成、补员、人物及援军关系 |
| 占领 | 占领、洗劫、夷平等可用选项与后果 |
| 边界与特殊建筑 | 港口、资源、地标及文化限制 |

不将腐蚀、气候适应、秩序和辐射污染自动合并为一个值。不同原版系统有不同接口和 AI 逻辑。

### 六、经济和招募

经济至少整理：建筑收益、贸易、战斗与战后收益、洗劫与劫掠、外交支付、建设、招募、维护、行动成本，以及适用的额外军队成本规则。

招募至少整理：本地与全局、槽位、时间、费用、初始等级、前置、容量、特殊池、冷却、补员及跨地区限制。盟军招募、雇佣、复活、升级转换等作为文化例外单列，不视为普通招募的同义词。

### 七、文化机制的原版观察分类

| 机制方向 | 应查找的原版实例与问题 |
| --- | --- |
| 有限高级兵力 | 容量、解锁、补充和 AI 招募；兄弟会容量方向的参考 |
| 多资源经营 | 生产、消耗、交换与限制，是否有必要承担此成本 |
| 文化政治 | 席位、权威、关系或其他政治表达，具体状态按版本核对 |
| 战后与征服成长 | 战果如何转换成收益、兵力或权限 |
| 游牧／军队建筑 | 是否依附军队，如何与领土并存 |
| 地下／异地据点 | 归属、发现、建设与收益的独立关系 |
| 腐蚀／传播 | 地区影响及反制 |
| 特殊招募与单位成长 | 经验、资源、战果或其他解锁 |
| 仪式／行动／全局能力 | 成本、冷却、作用范围和 UI 依赖 |

上述是后续原版实例调查的目录，不代表所有方向都适合本项目，或已找到可直接移植实现。

### 八、三条成长线的分工检查

建筑主要回答在哪里、以什么条件获得发展能力；科技回答派系长期选择；人物技能回答这个人及其军队如何成长。

同一个单位可以同时受三者影响，但要检查是否重复叠加到失去反制。文化设计时把建筑、科技、领主红线、事务官和特性对同一兵种的效果一起审阅。

### 九、派系经营设计交付表

科技树结构与节点组、建筑链与地标、资源收支、招募解锁、驻军和秩序、地区差异、文化机制。每项关联原版参考、作用范围和技术状态，未采用项写明原因。


## 附录D：战役、战斗与进程

### 一、开局、移动与军队状态

| 方面 | 原版参考检查内容 |
| --- | --- |
| 开局 | 派系领袖、起始城镇、军队、人物、建筑、科技、资源、外交与初始任务 |
| 军队组成 | 领主、事务官、普通单位、可用位置与特殊例外 |
| 移动 | 行动力、地形、道路、河流、海域和控制区 |
| 姿态 | 常规、急行、扎营、伏击、劫掠及文化特殊姿态；各姿态的移动、补员、招募和交战条件 |
| 视野 | 军队、事务官、城市、盟友、潜伏与侦察 |
| 补给与损耗 | 补员条件、损耗来源、围城、地区与免疫，不自动等于弹药物流 |
| 增援 | 距离、方向、时间、被阻止的条件与援军组成 |
| 海上行动 | 运输、遭遇及自动结算／转为陆战的具体处理；不预设海战可制作 |
| 军队管理 | 招募、转移、合并、解散、替换领主与特殊文化限制 |

### 二、外交与内部关系

战争、和平、互不侵犯、贸易、军事通行、防御或军事联盟、共同战争、附庸、合邦、支付和领土相关交易等按实际文化可用性登记。

每项核对：签订条件、AI 接受因素、关系变化、违约后果、可靠性、战争目标、同文化或跨文化限制。

盟军协调、前哨与盟军招募等分别记录，不把联盟视为自动共享全部兵表。合邦需要核对文化限制、领土人物归属与后续状态。

内部忠诚、权威、效忠和统一属于不同机制；先找具体原版参考，不能只用统一背景词汇替代规则。

### 三、战斗规则覆盖

| 方面 | 应整理内容 |
| --- | --- |
| 布阵 | 部署区、先锋部署、隐藏与初始朝向 |
| 地形 | 高低差、森林、障碍、视线与射界、通行宽度 |
| 接敌 | 正侧背、包围、冲锋、防冲锋、质量与碰撞 |
| 战斗控制 | 队形、编组、守卫、散兵、射击开关及适用指令 |
| 士气 | 局部损失、领主、恐惧惊骇、溃逃与不溃或特殊崩溃 |
| 状态 | 疲劳、隐蔽、火焰、毒素及其他接触效果 |
| 特殊行动 | 飞行与落地、攻门、攻击可破坏目标等实际权限 |
| 结果 | 胜负、追击、存活、经验、伤亡和俘虏相关处理 |
| 自动结算 | 单位数值与实战表现差异、特殊能力和驻军，单独检验 |

### 五、场景、攻城与防御

| 类型／元素 | 原版参考问题 | 对本项目的检查意义 |
| --- | --- | --- |
| 野战 | 开阔地、遮挡、部署与增援 | 基础军队配合是否成立 |
| 伏击 | 队列、部署与脱离／胜利规则 | 地形与机动文化的机会 |
| 无墙聚落 | 街道、目标点与防御位置 | 废土城市战优先比较的参考 |
| 有墙城镇 | 城墙、门、塔、内城与目标 | 哪些需要保留，哪些可简化 |
| 路障与防御设施 | 位置、供应、建造、摧毁、重建与控制点 | 可破坏工事的具体原型 |
| 攻城器械 | 建造、携带、部署、目标与 AI | 换皮不自动改变登墙／撞门用途 |
| 特殊任务战 | 预设目标、触发、援军和脚本 | 可用于特定事件，不默认替代所有城市战 |

城墙、建筑、可破坏工事、装饰物与导航碰撞分别登记。摧毁后的视觉、能否通行、能否射击、AI 是否改道是四项不同结果。

城市战候选方向：弱化传统城墙，防守依托街区与工事；进攻利用火力与破障推进。动态建筑破坏、攻城工具改造和战前爆破均未技术定稿。

重点核验：多条路径、直射视线、炮兵部署、怪兽和载具体积、驻军、撤退与援军、攻防 AI、自动结算，以及战役建筑如何选择对应战斗场景。

### 六、事件、任务与奖励

| 形式 | 应检查 |
| --- | --- |
| 提示与事件 | 触发条件、接收对象、频率和信息内容 |
| 两难选择 | 选项、成本、奖励、后果与 AI 决策 |
| 任务链 | 前置、阶段、奖励、失败、替代条件 |
| 任务战斗 | 触发、地图、部队、胜利条件和返回战役 |
| 人物／装备解锁 | 唯一性、获取与死亡后状态 |
| 地区或文化事件 | 归属变化、进入、占领或其他适用条件 |
| 后期冲突 | 触发时间或条件、力量配置、外交变化与结束 |

所有持久内容检查重复触发、目标死亡、派系灭亡、地区易主、保存载入与多人模式适用范围。具体支持何种模式另行决定。

### 七、战役目标与节奏

检查短期与长期目标、控制地点、击败对象、战斗或征服数量、机制目标、奖励和胜利后的继续游玩。危机、剧情主线与自由扩张不是同一设计层。

并非所有派系必须拥有独立任务战或独特末日事件。先明确不同开局能否形成各自的战争选择与完成方向。

### 八、信息、声音与交付覆盖

选择派系界面、单位卡、技能科技描述、前置提示、地图图标、事件消息、战斗状态说明、语音与音乐应与实际规则一致。

同时登记：战役可用性、自定义战斗可用性、AI、自动结算、保存载入、必要内容依赖和游戏构建。功能在一种模式可用不能外推到其他模式。

### 九、派系设计的完整对照输出

按[统一对比表](./战锤设计对比参考表.md)的 SYS 项及适用细分项填写采用状态、原版实例、辐射表达、技术未知项、关联功能说明及验收方向。通用沿用项简要登记，不作为新核心机制开发；未采用或待定项明确标注。


## 附录E：能力来源、约束与组合

### 四、按技能来源区分

| 来源 | 设计用途 | 不应默认的能力 |
| --- | --- | --- |
| 人物自身 | 嗑药、指挥、专业技术 | 不能无条件影响远处所有人 |
| 装备绑定 | 有限特殊武器、治疗或护盾装备 | 不自动共享统一弹药或生产系统 |
| 单位能力 | 喷火、投弹、超频等单位动作 | 原单位无相应动作时不能只改图标 |
| 事务官支援 | 医疗、工程、火力观察等专业能力 | 不自动获得全图投送和召唤 |
| 军队／派系能力 | 场外炮兵、空军支援 | 不要求生成可操作的实体支援单位 |
| 地区／建筑条件能力 | 特定设施提供支援 | 需要确认战役条件如何影响战斗能力 |

### 五、消耗与约束方式

| 方式 | 适合方向 | 设计提醒 |
| --- | --- | --- |
| 冷却 | 常规指令、可重复装置 | 不必同时提供强大伤害 |
| 每战次数 | 药剂、特殊弹药、有限支援 | 适合稀缺资源的抽象表达 |
| 开场等待与释放延迟 | 场外支援、重型打击 | 给对手预警和调整机会 |
| 条件充能 | 特定军队能力 | 仅选已有合适条件，不先造新资源 |
| 共享能力资源 | 适合的技术支援体系 | 魔法之风不能只改名就当成全部药品、弹药与燃料 |
| 战役前提 | 装备、技能、建筑、科技或地区条件 | 是否在当前战斗正确可用，另行核对 |

优先建议有限装备和大威力支援使用每战次数、延迟等现成约束；常规指令采用冷却。仍是设计建议，不强制将所有法术改成同一消耗模型。

保留每战次数的药物，不自动要求建立战役药品库存；若没有必要，不增加此类经营系统。

### 六、典型组合候选

| 概念 | 效果与形态组合 | 应避免的误读 |
| --- | --- | --- |
| 战斗兴奋剂 | M01 自身增益＋次数限制 | 不等于全军无条件加成 |
| 毒气弹 | S01 投射或 S04 投送＋S07 固定区域＋可选 M05 | 毒素接触减益不自动等于持续掉血 |
| 小型战术核弹 | S01 或 S03 的爆炸原型＋少量次数＋预警 | 爆炸不自动产生持久辐射、不自动摧毁建筑 |
| 场外炮击 | S04 区域轰击＋军队能力 | 战场无实体炮兵也可作为表现方案，但需原型支持 |
| 空中扫射 | S05 线性打击或 S04 覆盖＋军队能力 | 有伤害不等于已有飞越飞机动画 |
| 医疗支援 | M08＋单目标或区域作用 | 恢复生命与复活死亡模型分开 |
| EMP 类干扰 | M04／M05＋目标类型限制 | 不默认所有单位均是机械，过滤规则需验证 |
| 空降机器人 | M11 临时召唤 | 原地生成与空降过程的表现是两个工作项 |

### 七、能力卡的最小字段

标识、目的、M 类型、S 形态、原版原型、来源、合法目标、范围、友伤、时间、次数／资源、伤害与抗性、提示、视觉声音、AI、特殊单位差异、自动结算及项目验证状态。

嗑药不会自动影响机械，维修也不应自动作用于人类。是否进行这种区分，取决于目标筛选的成本与实际玩法必要性。

### 八、技术验证与资料边界

本稿未验证自定义目标筛选、法术改能力、资源去除、飞越动画、召唤退场或战役支援条件。选择具体原型后再为这些问题制定最小试验，不因文档存在而执行测试。

攻击的魔法属性、法术来源和破甲是不同维度；不应以科技背景直接推导伤害规则。[官方伤害说明](https://community.creative-assembly.com/total-war/total-war-warhammer/blogs/6-feature-focus-2-damage-part-1)


## 附录F：飞行与空中支援

### 一、四种实现目标分别考虑

| 形式 | 玩家得到什么 | 数量／时间约束候选 | 主要成本 |
| --- | --- | --- | --- |
| 场外空中支援 | 一次扫射、轰炸等能力，不操作飞机 | 次数、冷却、延迟、战役条件 | 能力、预警和特效；飞机飞越动画另算 |
| 临时可操作飞行单位 | 一段时间内加入战斗的单位 | 召唤次数、时限、退场规则 | 完整单位资产与飞行动作，加召唤和退场处理 |
| 常驻精英飞行单位 | 编入军队、参加后续战斗 | 招募条件、维护、容量 | 完整兵种、成长、补员与 AI |
| 飞行生物／怪兽 | 可常驻或临时出现的生物部队 | 按兵种职责决定，不默认全部稀有 | 生物骨架动作、近战、落地和死亡表现 |

四者可以按不同文化组合，但不要求各文化都拥有空军。临时召唤并不必然比常驻单位制作便宜：它仍可能需要完整模型和动作，且多出退场问题。

### 二、战术职责

| 职责 | 需要的原版行为 | 关键反制和限制 |
| --- | --- | --- |
| 空中近战 | 对空接敌、攻击动作 | 对空火力、其他飞行单位 |
| 落地突击 | 可落地并与地面目标交战 | 脱离、反大型、地面集火 |
| 空中机动射击 | 飞行、射角与射击 | 弹药、射程和地面反击 |
| 有限投弹 | 指定投弹或范围能力 | 释放次数、飞越风险和预警 |
| 重型单体突破 | 大型飞行形态及合适攻击 | 稀缺、维护、受击面积 |
| 骚扰与追击 | 速度与适合攻击方式 | 脆弱、输出有限和操作成本 |

少量飞行单位也能占据很多战术空间。评价的是威胁、反制和可用性，不只比较兵种数量。

### 三、背景与原型候选

| 候选形象 | 战锤参考方向 | 当前判断 |
| --- | --- | --- |
| 飞行器 | 飞行射击或投弹平台 | 优先选兼容运动方式；不默认能直接套用固定翼或直升机动作 |
| 小型飞行机器人 | 小型飞行单位或合适平台 | 是否能低成本表达取决于原型，不承诺新骨架 |
| 变异蝙蝠 | 蝙蝠类或飞兽原型 | 可作为原创候选，需确定规模、归属与动作 |
| 辐射吸血蚊、辐射大黄蜂等 | 小型虫类、群体飞行或其他相近原型 | 属于本项目架空候选，不自动纳入首版，也不以此扩展其他作品地图 |
| 大型变异飞兽 | 现有大型飞兽 | 先评估是否确有必要，避免只为补兵种制造终极怪兽 |

原创生物只在既定内容范围内作为必要补充，是否采用需后续确认。拥有飞行生物不意味着相关派系可以无背景解释地驯养全部物种。

### 四、建议的整体取舍

1. 飞行器可优先评估场外支援或数量有限的精英，符合稀缺感，也可控制常驻空军普及程度。
2. 飞行生物允许承担不同于科技空军的近战、追击和骚扰职责。
3. 不为每文化补一套对称空军。可用地面射击、专业反大型和其他已有能力建立反制。
4. 区分“反装甲”“反大型”“对空”：武器伤害高不代表能瞄准空中目标，具体射角和合法目标需要原型核对。
5. 空中能力与实体飞行单位都要考虑 AI 使用和自动结算差异；城市无墙不代表空军不会绕过核心防御。

### 五、临时单位专项检查

需要明确：谁能召唤、可在哪里出现、是否受玩家控制、可否落地、何时离场、是否计入损失和胜负、是否成为战役存活单位、释放者死亡后的行为、AI 是否使用。

借用具有衰减或消散的召唤原型时，不能直接把其死亡表现称为“飞机返航”。真实返航、离场消失和按原型衰减是不同结果，必须选择可接受的表现。

### 六、后续验证入口

选择具体单位时验证：飞行移动与转向、对空对地攻击、射角、落地、碰撞、死亡、地形与城市内表现；选择支援能力时验证：预警、投送、友伤、次数、飞机表现和 AI。

当前只记录设计方向，不创建新的飞行资产、不执行召唤或飞行试验，也不把所有候选列为必须交付。
